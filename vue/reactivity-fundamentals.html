Reactivity Fundamentals ​

ref() і .value ​

js
import { ref } from 'vue'

const count = ref(0)
console.log(count.value) // 0
count.value++            // у JS — завжди через .value
  • ref() обгортає значення в об'єкт з властивістю .value.
  • У шаблоні .value писати не треба — top-level ref автоматично розгортається:
template
<button @click="count++">{{ count }}</button>

Навіщо ref, а не звичайна змінна? ​

У JS неможливо відстежити читання чи зміну звичайної змінної. Зате можна перехопити get/set властивості об'єкта. Тому Vue ховає значення за .value: у getter — track() (запам'ятати залежність), у setter — trigger() (перерендерити залежні компоненти).

js
// псевдокод
const myRef = {
  _value: 0,
  get value() { track(); return this._value },
  set value(v) { this._value = v; trigger() }
}

Бонус: ref можна передати у функцію — вона бачитиме актуальне значення і реактивний зв'язок збережеться.

Глибока реактивність ​

ref може зберігати будь-що (об'єкти, масиви, Map). Вкладені зміни теж відстежуються — об'єкти всередині ref проходять через reactive():

js
const obj = ref({ nested: { count: 0 }, arr: ['foo'] })
obj.value.nested.count++ // реактивно
obj.value.arr.push('bar') // реактивно

shallowRef() — відстежується лише заміна .value, без глибокого спостереження. Для оптимізації великих об'єктів або коли станом керує зовнішня бібліотека.

Коли оновлюється DOM — nextTick() ​

DOM оновлюється не синхронно: Vue буферизує зміни до «наступного тіку», щоб кожен компонент оновився один раз, скільки б змін не було.

js
import { nextTick } from 'vue'

async function increment() {
  count.value++
  await nextTick()
  // тут DOM вже оновлений
}

reactive() ​

Робить реактивним сам об'єкт (без .value). Повертає Proxy, який перехоплює доступ і зміну всіх властивостей. Глибокий (є shallowReactive()).

js
const state = reactive({ count: 0 })
state.count++

Proxy ≠ оригінал ​

js
const raw = {}
const proxy = reactive(raw)

proxy === raw            // false — реактивний лише proxy
reactive(raw) === proxy  // true — той самий proxy
reactive(proxy) === proxy // true

Зміни оригіналу не тригерять оновлення → працюй тільки з proxy. Вкладені об'єкти теж стають proxy (proxy.nested = raw; proxy.nested === raw // false).

Обмеження reactive() — чому рекомендують ref() ​

  1. Тільки об'єкти (object, array, Map, Set) — примітиви не можна.
  2. Не можна замінити весь об'єкт — зв'язок з попереднім втрачається:
    js
    let state = reactive({ count: 0 })
state = reactive({ count: 1 }) // старий більше не відстежується
  3. Деструктуризація втрачає реактивність (як і передача примітивної властивості у функцію):
    js
    let { count } = state
count++                       // state.count не зміниться
callSomeFunction(state.count) // передається просто число

Через це Vue рекомендує ref() як основний API.

Розгортання ref усередині reactive ​

Ref як властивість reactive-об'єкта розгортається автоматично:

js
const count = ref(0)
const state = reactive({ count })

state.count      // 0 (без .value)
state.count = 1
count.value      // 1

Присвоєння нового ref замінює старий (старий відв'язується). У shallowReactive розгортання немає.

Масиви і колекції — НЕ розгортаються ​

js
const books = reactive([ref('Vue 3 Guide')])
books[0].value // потрібен .value

const map = reactive(new Map([['count', ref(0)]]))
map.get('count').value // потрібен .value

Підступ: розгортання в шаблонах ​

У шаблоні розгортаються лише top-level refs.

js
const count = ref(0)
const object = { id: ref(1) }
ВиразРезультатЧому
{{ count + 1 }}1count — top-level
{{ object.id + 1 }}[object Object]1object.id не розгорнутий, це ref-об'єкт
{{ object.id }}1ref — кінцеве значення інтерполяції, розгортається (= object.id.value)

Фікс — деструктуризувати в top-level:

js
const { id } = object
template
{{ id + 1 }} <!-- 2 -->
