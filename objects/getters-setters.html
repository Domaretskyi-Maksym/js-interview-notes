Гетери і сетери в об’єктах ​

Гетери і сетери — це спеціальний вид властивостей об’єкта, які називаються властивостями-аксесорами (accessor properties).

Звичайні властивості vs аксесори ​

Вид властивостіЩо зберігаєЯк працює
Властивість данихКонкретне значення (value)Просто читаєш/записуєш
АксесорФункції get і/або setПри читанні викликається get, при записі — set

Зовні аксесор виглядає як звичайна властивість, але всередині виконуються функції.

Базовий приклад ​

js
let user = {
  name: "Тарас",
  surname: "Мельник",

  // Гетер — викликається, коли читаємо user.fullName
  get fullName() {
    return `${this.name} ${this.surname}`;
  },

  // Сетер — викликається, коли пишемо user.fullName = ...
  set fullName(value) {
    [this.name, this.surname] = value.split(" ");
  }
};

console.log(user.fullName); // "Тарас Мельник"  ← спрацював гетер

user.fullName = "Аліса Бондар"; // спрацював сетер

console.log(user.name);     // "Аліса"
console.log(user.surname);  // "Бондар"

Ми не викликаємо user.fullName() як функцію. Ми просто читаємо/пишемо властивість, а JavaScript сам викликає потрібну функцію.

Для чого вони потрібні? ​

1. Віртуальні (обчислювані) властивості ​

Коли значення не зберігається напряму, а обчислюється на льоту:

js
let product = {
  price: 1000,
  discount: 0.15,

  get finalPrice() {
    return this.price * (1 - this.discount);
  }
};

console.log(product.finalPrice); // 850

2. Валідація і контроль даних (найчастіше використовують) ​

Хочемо захистити властивість від некоректних значень:

js
let user = {
  get name() {
    return this._name;
  },

  set name(value) {
    if (value.length < 3) {
      console.log("Ім’я занадто коротке!");
      return;
    }
    this._name = value;
  }
};

user.name = "Ян";     // Ім’я занадто коротке!
user.name = "Олександр";
console.log(user.name); // "Олександр"

Підкреслення _name — це домовленість: «ця властивість внутрішня, не чіпай її напряму».

3. Сумісність зі старим кодом ​

Раніше був age, а тепер вирішили зберігати birthday. Старий код ламати не хочеться:

js
function User(name, birthday) {
  this.name = name;
  this.birthday = birthday;

  Object.defineProperty(this, "age", {
    get() {
      const today = new Date();
      return today.getFullYear() - this.birthday.getFullYear();
    }
  });
}

const john = new User("Іван", new Date(1995, 5, 15));

console.log(john.age);      // працює (обчислюється)
console.log(john.birthday); // теж працює

Старий код, який читає user.age, продовжує працювати.

4. Логування / додаткові дії ​

js
let account = {
  _balance: 1000,

  get balance() {
    console.log("Хтось перевіряє баланс");
    return this._balance;
  },

  set balance(value) {
    console.log(`Баланс змінено з ${this._balance} на ${value}`);
    this._balance = value;
  }
};

Важливі правила ​

  1. Властивість може бути або звичайною (має value), або аксесором (має get/set). Одночасно — не можна.
  2. Можна зробити тільки гетер (тоді властивість тільки для читання).
  3. Можна зробити тільки сетер (тоді властивість тільки для запису).
  4. Через Object.defineProperty можна створювати аксесори динамічно.

Коли варто використовувати? ​

  • Коли потрібно обчислювати значення на льоту.
  • Коли потрібно перевіряти значення перед записом.
  • Коли хочеш приховати внутрішню логіку, але залишити зручний інтерфейс.
  • Коли потрібно зберегти сумісність зі старим кодом.

Не варто використовувати гетеры/сетери просто так — для звичайних даних краще звичайні властивості. Вони потрібні саме тоді, коли потрібна додаткова логіка при читанні або записі.
